Обновление через интерфейс командной строки (CLI) позволяет выполнить процесс обновления непосредственно на сервере, минуя ограничения веб-сервера по тайм-ауту и размеру загружаемых файлов.
Этот способ рекомендуется использовать для крупных баз данных или в тех случаях, когда при работе *Мастера обновления* возникали ошибки из-за тайм-аута.

{{% notice warning %}}
Перед началом работы убедитесь, что выполнены все шаги, описанные в разделе
link:../before-you-upgrade[Подготовка к обновлению^], включая создание резервной копии экземпляра системы.
{{% /notice %}}

== Выбор способа

В зависимости от версии SuiteCRM, доступны два способа обновления через командную строку:

[cols="1,1"]
|===
|Способ |Требования к версии

|`robo upgrade:suite` |SuiteCRM 7.11.3 и новее
|`silentUpgrade.php` |Все версии 7.x
|===

Используйте команду *robo*, если ваша версия SuiteCRM её поддерживает. Скрипт *silentUpgrade.php* предназначен для использования в качестве альтернативного варианта для более старых версий системы.

== Первый способ: Команда Robo (для версий 7.11.3+)

=== Размещение пакета обновления

Загрузите соответствующий пакет обновления с https://suitecrm.com/releases/[этой^] страницы и скопируйте его в корневой каталог установки SuiteCRM.

=== Запуск обновления

Находясь в корневом каталоге SuiteCRM, выполните следующую команду:

[source,bash]
----
./vendor/bin/robo upgrade:suite <upgradeZipFile> <logFile> <pathToSuiteCRMInstance> <adminUser>
----

[cols="1,3"]
|===
|Аргумент |Описание

|`upgradeZipFile` |Путь к ZIP-файлу обновления (например, `SuiteCRM-Upgrade-7.14.x-to-7.15.0.zip`)
|`logFile` |Путь и имя файла для записи логов (например, `upgrade.log`)
|`pathToSuiteCRMInstance` |Абсолютный путь к каталогу установки SuiteCRM Если команда выполняется из корневого каталога, используйте `.` 
|`adminUser` |Имя пользователя учётной записи администратора SuiteCRM
|===

Пример:

[source,bash]
----
./vendor/bin/robo upgrade:suite SuiteCRM-Upgrade-7.14.x-to-7.15.0.zip upgrade.log . admin
----

== Второй способ: silentUpgrade.php (для всех версий)

=== Размещение пакета обновления

Загрузите пакет обновления и скопируйте его в место, доступное с сервера с установленной системой. Запомните полный путь к файлу.

=== Запуск скрипта

[source,bash]
----
php -f <путь-к-suitecrm>/modules/UpgradeWizard/silentUpgrade.php \
 <upgradeZipFile> <logFile> <pathToSuiteCRMInstance> <adminUser>
----

[cols="1,3"]
|===
|Аргумент |Описание

|`upgradeZipFile` |Полный путь к ZIP-файлу обновления
|`logFile` |Полный путь к файлу журнала (будет создан, если еще не существует)
|`pathToSuiteCRMInstance` |Полный путь к каталогу установки SuiteCRM
|`adminUser` |Имя пользователя учетной записи администратора SuiteCRM
|===

Пример:

[source,bash]
----
php -f /var/www/suitecrm/modules/UpgradeWizard/silentUpgrade.php \
/tmp/SuiteCRM-Upgrade-7.14.x-to-7.15.0.zip \
/var/www/suitecrm/upgrade.log \
/var/www/suitecrm \
admin
----


== Настройка прав доступа после завершения обновления

Все файлы, созданные в процессе обновления, будут принадлежать пользователю, от имени которого выполнялась команда — в серверной среде это часто пользователь *root*. Если веб-сервер (например, Apache) работает от имени другого пользователя, он не сможет читать эти файлы или записывать в них данные, что приведет к сбоям в работе приложения. После завершения обновления восстановите права доступа:

[source,bash]
----
# Укажите пользователя и группу в соответствии с настройками веб-сервера (например, www-data:www-data или apache:apache)
chown -R www-data:www-data /path/to/suitecrm
find /path/to/suitecrm -type d -exec chmod 755 {} \;
find /path/to/suitecrm -type f -exec chmod 644 {} \;
----

== Действия после обновления

. Восстановите права доступа к файлам, как описано выше.
. Войдите в систему под учётной записью администратора, перейдите в раздел menu:Администрирование[Восстановление] и выполните операции *Перестройка связей* и *Быстрое восстановление*.
. Если перед обновлением вы отключали кеширование, включите его снова.

== Устранение неполадок

Подробную информацию об ошибках можно найти в файле журнала, который был указан в вышеуказанной команде обновления. Журнал мастера обновления  сохраняется по следующему пути:

----
<suitecrm-root>/upgradeWizard.log
----

См. также разделы
link:../troubleshooting/logs[Журналы обновления^] и link:../troubleshooting/known-issues[Проблемы при обновлении^].
