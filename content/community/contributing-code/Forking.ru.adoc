== Краткое руководство по созданию форка SuiteCRM

=== Создание форка репозитория SuiteCRM

Форк можно сделать непосредственно на сайте GitHub. Подробности описаны в статье
https://help.github.com/articles/fork-a-repo/[Forking a repo^] в справке GitHub.

=== Настройка Git на локальном компьютере

Воспользуйтесь руководством от
https://help.github.com/articles/set-up-git/[GitHub^], в котором содержатся
подробные инструкции по настройке Git и подключению к GitHub с вашего
локального компьютера.

=== Клонирование репозитория на локальный компьютер

После настройки Git и создания форка на GitHub можно клонировать репозиторий
на свой локальный компьютер. Перейдите в нужную директорию и выполните
следующую команду для клонирования репозитория SuiteCRM (заменив
`username` на ваше имя пользователя в GitHub):

[source, console]
git clone git@github.com:username/SuiteCRM.git

Теперь, когда репозиторий клонирован, необходимо настроить удалённые репозитории, на которые он будет ссылаться.
По умолчанию Git создает
удаленный репозиторий с именем `origin`, который указывает на ваш форк
на GitHub (https://github.com/username/SuiteCRM).

Однако, чтобы иметь возможность
получать обновления из родительского репозитория, следует также добавить удаленный репозиторий с именем `upstream`.

Сделать это можно следующим образом:

[source, console]
----
cd SuiteCRM
git remote add upstream git@github.com:SuiteCRM/SuiteCRM.git
git fetch upstream
----

Теперь вы сможете легко обновлять свой форк в любое время.
Просто переключитесь на ветку, которую вы хотите обновить из исходного репозитория (upstream) — например, на ветку `master`, — а затем выполните следующие команды:

[source, console]
----
git checkout master
git fetch upstream
git merge upstream/master
git push origin master
----

Эти команды загрузят последние изменения из исходного репозитория в ваш локальный репозиторий, объединят их с веткой `master` в вашей локальной копии, а затем отправят эти изменения в ваш форк на GitHub. Это необходимо для поддержания актуального состояния ваших веток *master*, *hotfix* и *develop* после выхода минорных или мажорных релизов.
