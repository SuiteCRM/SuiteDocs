== Стандарты написания кода для SuiteCRM

В структуре PHP-кода SuiteCRM наблюдается некоторая несогласованность стилей.
Команда SuiteCRM работает над постепенным устранением этих различий, помогая как штатным разработчикам, так и внешним участникам придерживаться единого стиля. Это позволит сделать код более чистым и легким для восприятия. Данный процесс будет продолжаться некоторое время, однако мы призываем пользователей уже сейчас приводить предлагаемые исправления ошибок и улучшения в соответствие с приведенными ниже стандартами. Благодарим вас за ваш вклад в развитие проекта!

== Отступы

Используйте стандарт оформления отступов https://www.php-fig.org/psr/psr-2/#24-indenting[PSR-2].

В коде ДОЛЖНЫ использоваться отступы размером в *4 пробела*; использование символов табуляции для отступов ЗАПРЕЩЕНО.

В файлах JavaScript следует использовать отступы размером в *2 пробела*.

== Имена классов

Имена классов должны быть записаны в формате *StudlyCaps* (например, `ClassName`, `DoSomething`).
Названия классов должны соответствовать сущности, которую они описывают.

.Пример:
[source, php]
----
class YoungInfant extends Person
{

}
----

== Имена функций

Имена функций должны быть записаны в формате *lower camelCase* (например, `functionName`, `doSomething`).
Названия функций должны быть описательными и, желательно, содержать глагол.

.Пример:
[source, php]
----
function printLoginStatus($user, $time)
{
// Do Something
}
----

Имена аргументов функций должны отражать назначение соответствующих переменных.

== Переменные

Статические переменные и свойства класса должны быть записаны в формате *lower camelCase*.
Не следует без необходимости сокращать имена переменных.

.Пример:
[source, php]
----
public static $jobStrings;

var $disableRowLevelSecurity = true;
----

Кроме того, перед использованием неинициализированных переменных проверяйте их наличие с помощью встроенной функции `isset()`.

.Пример:
[source, php]
if (isset($forum))

== Кавычки

Используйте одинарные или двойные кавычки в зависимости от ситуации. Если внутри строки не требуется вычисление выражений, используйте одинарные кавычки. В таких случаях нет необходимости экранировать кавычки внутри строки.

.Пример:
[source, php]
----
$sample = 'Hello';
$sample = "Hello, $name";
$sample = "Hello, \{$name}";
----

== Массивы

При объявлении индексированных массивов после каждой запятой, разделяющей элементы, необходимо ставить пробел — это улучшает читаемость кода.

.Пример:
[source,php]
$sampleArray = [1, 2, 3, 'Zend', 'Studio'];

При объявлении многострочного индексированного массива первый элемент может располагаться на следующей строке. В этом случае он должен иметь отступ на один уровень больше, чем строка, содержащая объявление массива; все последующие строки должны иметь такой же отступ. Закрывающая квадратная скобка должна находиться на отдельной строке с тем же уровнем отступа, что и строка с объявлением массива.

.Пример:
[source,php]
----
$sampleArray = [
   1, 2, 3, 'Zend', 'Studio', 
   $a, $b, $c, 
   56.44, $d, 500, 
];
----

При объявлении ассоциативных массивов первый элемент также может располагаться на следующей строке. В этом случае он должен иметь отступ на один уровень больше, чем строка, содержащая объявление массива; все последующие строки должны иметь такой же отступ. Закрывающая квадратная скобка должна находиться на отдельной строке с тем же уровнем отступа, что и строка с объявлением массива. Для улучшения читаемости операторы присваивания `=>` следует выравнивать относительно друг друга. 

.Пример:
[source, php]
----
$sampleArray = [
   'firstKey'  => 'firstValue', 
   'secondKey' => 'secondValue', 
];
----

== Стиль использования фигурных скобок

*Всегда используйте фигурные скобки*: Даже если они не требуются, все равно сохраняйте их для большей ясности кода.

.Не правильно:
[source, php]
----
if (condition) do_stuff();

if (condition)
   do_stuff(); 
----

.Правильно:
[source, php]
----
if (condition) 
{
   do_stuff(); 
}

if ($a !== 2) {
   $a = 2; 
} elseif ($a === 3) {
   $a = 4; 
} else {
   $a = 7; 
}
----

Открывающая скобка в именах классов, функций и методов должна располагаться на следующей строке,
как и объявление,  закрывающая скобка — также на отдельной строке.

.Пример:
[source, php]
----
class ThisClass 
{     
   public function newMethod()
   {

   } 
} 

function newFunction() 
{

} 
----

== Комментарии

Используйте синтаксис https://phpdoc.org/[phpdoc] перед всеми определениями классов/методов/членов/функций. Простой шаблон можно
настроить в вашей IDE.

* Все определения классов должны содержать как минимум `@author` и `@package`, причём `@author` должен находиться на последней строке блочного комментария.
* Блочные комментарии, содержащие phpdoc, всегда начинаются с двух звёздочек:
(`/** ... */`)
* Одиночный комментарий должен начинаться с пробела, за которым следует заглавная буква без точки: `// Это пример`

Подробно комментируйте любой сложный, неясный или иным образом не сразу очевидный код, чтобы описать действия, которые делает ваш код,
при необходимости опишите предварительные условия для его правильной работы. Разработчик должен иметь возможность взглянуть на любую часть приложения и за разумное время понять, что происходит.

.Пример:
[source, php]
----
/**
* Краткое описание метода
*
* Краткое описание этого метода, которое может занимать
* несколько строк – также предоставляет контекст
* для метода.
*
* @param string $variable с описанием этого аргумента
* @return void
*/
public function myMethod($variable) 
{
   // Do something here
} 
----

== Общие рекомендации

Любой новый класс (включая классы, созданные в сгенерированных файлах) должен использовать
конструктор `__construct`, но только там, где конструктор необходим.

.Пример:
[source, php]
----
public function __construct()
{
   // Do child class specific code here
   parent::__construct();
} 
----

и браузерами, указанными в

== Организационные моменты

Если вы используете файлы JavaScript, в основных файлах следует использовать минифицированную версию, а неминифицированную — в соответствующем каталоге,
внутри папки `jssource`. Любые изменения в файлах JavaScript следует вносить в папку `jssource`, а затем минифицировать в основные файлы.

Если вы вносите изменения в тему, необходимо предоставить минифицированную версию CSS.
Дополнительную информацию описана в
link:../../../../developer/extending-ui/theme/sass/[Руководстве по SASS^].

При разработке новой функции не создавайте файлы в пользовательском каталоге и убедитесь, что новое имя модуля является осмысленным и релевантным, без префиксов.

При добавлении нового модуля удалите лишние файлы, чтобы использовались только необходимые файлы. Ниже приведены примеры (но не ограничивающиеся ими)
упорядочивания каталога/файлов модуля.

* Удалите `studio.php`, если он не должен находиться в студии.
* Удалите файл класса `_sugar` из основного файла класса, если он не используется.
