Чтобы добавить новый функционал в SuiteCRM, необходимо создать форк репозитория SuiteCRM и настроить Git.

После этого создайте новую ветку на основе ветки `develop`. Название ветки должно отражать суть добавляемой функции, например: `campaign-wizard-ui`.
При разработке следуйте нашим
link:../coding-standards[стандартам написания кода] и поддерживайте форк в актуальном состоянии относительно новых релизов. Инструкции по обновлению репозитория можно найти в разделе
link:../forking[Создание форка SuiteCRM].

Убедитесь, что комментарии к коммитам информативны и точно описывают внесенные изменения. Когда все будет готово, создайте запрос на слияние (PR), подробно описав новый функционал.

При создании PR убедитесь, что в качестве целевого репозитория указан `SuiteCRM/SuiteCRM` (для версий 7.x) или `SuiteCRM/SuiteCRM-Core` (для версий 8.x), а в качестве целевой ветки — `develop`. В качестве исходного репозитория должен быть указан ваш форк, а в качестве исходной ветки — ветка с предлагаемым функционалом.

Если для новой функциональности (например, при добавлении модулей или классов) требуются тесты, добавьте их с использованием PHPUnit в ту же ветку.

== Проверка нового функционала

Мы проведем проверку кода и предоставим обратную связь непосредственно в PR или в issues, связанных с вашей разработкой. Если планируется включение этой функции в основной продукт, мы попросим вас активировать вкладку *Issues* в вашем форке — это позволит нам сообщать об ошибках, выявленных в ходе тестирования. Вы сможете исправлять эти ошибки, используя определенный формат сообщений к коммитам (аналогично тому, как это делается при исправлении ошибок для ветки `hotfix`):

.Пример:
[source,console]
----
git commit -m "Fixed #1436 - Reports with nested Parentheses are removing parameters"
----

{{% notice note %}}
Вкладку *Issues* можно добавить в ваш форк через раздел *Settings* репозитория.
{{% /notice %}}

Новый функционал, который будет принят, войдёт в следующий основной релиз проекта — например, версии 7.10 или 7.11 являются основными релизами. Минорные релизы содержат только исправления ошибок или внутренние доработки; примерами таких релизов могут служить версии 7.10.5 или 7.11.2.
