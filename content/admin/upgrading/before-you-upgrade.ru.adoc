Перед запуском процесса обновления выполните все пункты, описанные на этой странице, независимо от того, какой метод обновления вы используете.

== Проверьте таблицу совместимости

Убедитесь, что используемые вами версия PHP, база данных и веб-сервер поддерживаются целевой версией SuiteCRM.

link:../../compatibility-matrix[Посмотреть таблицу совместимости^]

Если установленное на сервере ПО требует обновления, запланируйте эти работы отдельно и выполните их до начала обновления SuiteCRM.

== Сначала протестируйте обновление в среде разработки

Никогда не выполняйте обновление непосредственно в рабочей среде. Создайте копию своей рабочей среды — включая файлы и базу данных — на сервере для разработки или тестирования и полностью выполните обновление там, прежде чем приступать к работам в основной системе.

Это особенно важно, если в  системе есть кастомные доработки. 
Детальная информация на эту тему описана в разделе
 link:../large-or-complex-upgrades[Подготовка к крупному обновлению].

== Создайте резервную копию системы

Перед обновлением обязательно создайте резервную копию файлов SuiteCRM и базы данных. Если в процессе обновления возникнут ошибки или проблемы, наличие актуальной резервной копии станет единственным надежным способом восстановления системы.

[source,bash]
----
# Пример: создание резервной копии базы данных
mysqldump -u <user> -p <database_name> > suitecrm_backup_$(date +%Y%m%d).sql
----

Убедитесь, что резервная копия сохранена за пределами корневого каталога SuiteCRM.

== Скачайте пакет обновления

Загрузите соответствующий пакет обновления с https://suitecrm.com/releases/[этой^] страницы.

Названия пакетов обновления имеют следующий формат:*SuiteCRM-Upgrade-7.x.x-to-7.x.x.zip*.
Убедитесь, что вы скачиваете пакет, предназначенный именно для вашей текущей версии.

== Настройте параметры PHP

Для процесса обновления требуются достаточно высокие лимиты в настройках PHP. Обновите файл `php.ini` (или соответствующий конфигурационный файл сервера), установив следующие минимальные значения:

[cols="1,1"]
|===
|Параметр |Минимальное значение

|`post_max_size`       |60M
|`upload_max_filesize` |60M
|`max_input_time`      |3000
|`max_execution_time`  |6000
|`memory_limit`        |256M
|===

Для применения внесённых изменений перезапустите веб-сервер.

{{% notice info %}}
Эти настройки актуальны, если используется **Мастер обновления** в веб-интерфейсе. Если вы обновляетесь через интерфейс командной строки (CLI), ограничения PHP для веб-запросов менее важны, однако параметр `memory_limit` также актуален при обновлении через CLI.
{{% /notice %}}

== Настройка параметров загрузки файлов

При использовании Мастера обновления необходимо также увеличить максимально допустимый размер загружаемого файла в самом SuiteCRM:

. Войдите в систему под учётной записью администратора.
. В меню пользователя выберите пункт menu:Администрирование[Параметры конфигурации].
. В подразделе *Дополнительные настройки*  установите для параметра *Максимальный размер загружаемого файла* значение `30000000` (30 МБ).
. Нажмите на кнопку {btn}[Сохранить].

== Отключение кеширования 

Если на вашем сервере используется кеширование (например, OPcache или APC), отключите его перед началом обновления. Устаревшие данные в кеше могут привести к некорректной работе обновленного приложения.

Включите кеширование снова после завершения обновления и проверки работоспособности системы.

== Проверка прав доступа к файлам

Во время процесса обновления пользователь, от имени которого работает веб-сервер, должен иметь права на запись в корневой каталог SuiteCRM и все вложенные папки. В ходе обновления происходит добавление, замена и удаление файлов в системе.

[source,bash]
----
# Пример: установка прав доступа в Linux (укажите пользователя/группу, соответствующие вашему веб-серверу)
chown -R www-data:www-data /path/to/suitecrm
----

{{% notice warning %}}
При выполнении обновления через интерфейс командной строки (CLI) помните, что все файлы, созданные в процессе обновления, будут принадлежать пользователю, от имени которого запущена команда, а не обязательно пользователю веб-сервера. Детали описаны в разделе
link:../cli-upgrade/#_настройка_прав_доступа_после_завершения_обновления[Установка прав доступа после завершения обновления^].
{{% /notice %}}

== Проверка возможности записи в файл config.php

Для работы Мастера обновления необходимо, чтобы файл `config.php`, расположенный в корневом каталоге SuiteCRM, был доступен для записи пользователю веб-сервера.

== Контрольный список

Перед началом убедитесь, что:

* [ ] Целевая версия совместима с используемыми версиями PHP, базы данных и веб-сервера
* [ ] Выполнено предварительное тестирование обновления в среде разработки
* [ ] Созданы резервные копии файлов и базы данных
* [ ] Загружен корректный пакет обновления
* [ ] Обновлены настройки PHP и перезапущен веб-сервер
* [ ] Максимальный размер загружаемого файла в SuiteCRM установлен на 30 МБ (только при использовании Мастера обновления)
* [ ] Отключено кеширование
* [ ] Пользователь веб-сервера имеет права на запись в корневой каталог SuiteCRM
* [ ] Файл `config.php` доступен для записи (только при использовании Мастера обновления)
