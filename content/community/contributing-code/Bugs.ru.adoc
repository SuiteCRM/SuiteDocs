== Исправление ошибок

* Чтобы предложить исправление ошибки, вам необходимо создать собственный форк репозитория SuiteCRM, внести изменения в код, сделать коммит и отправить запрос на слияние (PR, далее - PR)  в соответствующую ветку репозитория SuiteCRM.

Ознакомьтесь с  
link:../forking/[руководством по созданию форка SuiteCRM^]. После настройки форка вы сможете вносить в него изменения и создавать коммиты для проекта.

* При создании PR для SuiteCRM всегда направляйте его в ветку `hotfix`.
* При создании PR для SuiteCRM 8 также направляйте его в ветку `hotfix`.

{{%notice info%}}
Ветка `hotfix` будет позже объединена с веткой `develop`, которая, в свою очередь, будет объединена с веткой `master`.
{{%/notice%}}

* Для каждого исправления создавайте отдельную ветку в своем репозитории, включая в название идентификатор ошибки, например: _bugfix_3062_ или _issue-1234_.
+
Например, чтобы создать ветку на основе `hotfix`, используйте следующую команду git:
+
`git checkout -b _bugfix_3062_ upstream/hotfix`
+
* При создании коммитов в вашей отдельной ветке рекомендуется придерживаться следующего формата сообщения:
+
`Fix #1234 - <краткое описание проблемы>`
+
Пример команды для создания коммита:
+
`git commit -m "Fix #1436 - Reports with nested Parentheses are removing parameters"` +
+
Такой формат сообщений к коммитам позволяет нам легко включать информацию обо всех исправлениях ошибок в *примечания к релизу*.
+
Если вы еще не знакомы с правилами составления сообщений для коммитов в Git, ознакомьтесь с 
http://chris.beams.io/posts/git-commit/#seven-rules[этим^] руководством.

* При отправке ветки (push), созданной на основе ветки из репозитория-источника (upstream), в ваш удаленный форк, необходимо указать *origin*, например:
+
`git push origin _bugfix_3062_`

=== Перенос вашего PR с ветки 7.10.x на ветку hotfix

С 31 января 2022 года расширенная поддержка версии 7.10.x прекращена. Однако это не означает, что ваш PR, созданный для исправления конкретной ошибки или добавления новой функции, потерял свою актуальность!

Если проблема, с которой вы столкнулись, по-прежнему присутствует, а ваш PR был создан для версии 7.10.x, выполните следующие шаги, чтобы перенаправить его на ветку `hotfix`.

. Переключитесь на ветку, содержащую необходимое исправление.
 `git checkout <ваша-ветка>`

. Получите хеш первого коммита, сделанного вами в этой ветке, а затем последовательно соберите хеши всех последующих коммитов вплоть до самого последнего с помощью команды:
`git log -1 --format=format:"%H"`
+
Чтобы получить хеши всех коммитов, сделанных вами в этой ветке, замените число `1` в приведенной выше команде на общее количество ваших коммитов.

. Переключитесь на ветку `hotfix`.
`git checkout hotfix`

. Создайте новую ветку, которую вы затем будете использовать для обновления PR.
`git checkout -b <новая-ветка>`

. Перенесите свои коммиты с помощью команды `cherry-pick`.
`git cherry-pick commit1 commit2`
+
Вместо `commit1` и `commit2` подставьте хеши ваших коммитов.

При отправке новой ветки (push), содержащей те же изменения, что были в предыдущем PR, укажите ссылку на новый PR в старом, а затем закройте старый PR.

Впрочем, если вы уверенно пользуетесь Git, вы можете выполнить повторную отправку в ту же самую ветку и изменить основную ветку в PR на `hotfix` (при условии, что вы предварительно выполнили операцию `rebase`).

=== Создание PR для исправления ошибки

* После того как вы сделали коммиты и отправили их в свой форк репозитория, создайте 
http://help.github.com/articles/using-pull-requests[PR^], чтобы изменения были проверены и включены в основной репозиторий SuiteCRM. Создавайте отдельный PR для каждой исправленной ошибки — *не объединяйте* исправления нескольких ошибок в один PR.

* При создании PR убедитесь, что в качестве базового репозитория выбран *SuiteCRM/SuiteCRM*, а в качестве базовой ветки — `hotfix`.
Для SuiteCRM 8 убедитесь, что базовым репозиторием (base fork) является *SuiteCRM/SuiteCRM-Core*, а базовой веткой — `hotfix`.
При этом исходным репозиторием (head fork) должен быть *ваш репозиторий*, а веткой-источником — ваша отдельная ветка с исправлениями.

* Мы будем автоматически отклонять любые PR, направленные в неверную ветку!

=== Проверка CLA

Если вы ещё не подписали наше https://cla.suitecrm.com/SuiteCRM/SuiteCRM[CLA^], ваш PR не пройдет проверку и не сможет быть принят в проект. Подписать это соглашение нужно только один раз.

=== Travis CI

При создании нового пул-реквеста система Travis CI выполняет проверку слияния вашей ветки с целевой веткой и обновляет статус PR. Если проверка завершилась неудачей, вы можете ознакомиться с результатами тестирования и внести необходимые исправления. Чтобы провести тестирование до отправки PR, установите PHPUnit через composer в среде разработки, перейдите в директорию `tests` и выполните команду:

`sh runtests.sh`
